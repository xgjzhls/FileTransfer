TURN：最后手段与它的成本

第 6 课 · 打洞失败时的兜底。数据绕道服务器，保证几乎总能连上——但每一字节都要付带宽钱。本课回答：TURN 怎么工作、为什么是最后手段、部署时要防什么。

🎯 本课实得收获：上完这课，你能说出 TURN 的三个核心机制（Allocate / Permission / Channel），解释「为什么 TURN 必须只做兜底」，以及你未来部署时要防的三种坑。

什么时候需要 TURN

第 3、5 课已经给了答案：对称 NAT、防火墙禁 UDP、运营商级 NAT 没有 hairpin……这些场景下打洞和 STUN 都失效。RFC 5766（TURN）引言直接说了打洞的边界：

If both hosts are behind NATs that have a mapping behavior of address-dependent mapping or address- and port-dependent mapping, then hole punching techniques generally fail. … it is best to use a TURN server only when a direct communication path cannot be found.

—— RFC 5766 §1 Introduction

ICE 天然遵守这个次序：候选优先级里 relay 通常为 0（最后手段）——host、srflx 全试过都不通，才轮到 TURN（第 4 课）。

TURN 的三个核心机制

1. Allocation（分配）

客户端向 TURN 服务器发 Allocate 请求，服务器在公网分配一个 relayed transport address（中继传输地址）——这就是你的 relay 候选者。流程（RFC 5766 §2.2）：

Client ──Allocate(无凭据)──▶ Server
Client ◀──401 Unauthorized── Server      ← 先要认证
Client ──Allocate(带凭据)──▶ Server
Client ◀──relayed addr───── Server      ← 分配成功，得到中继地址

分配的默认寿命 10 分钟，之后必须周期性发 Refresh 续命（否则资源被回收）。一个分配可以同时与多个对端通信——数据包总是标明「发给哪个对端」，这比 SOCKS（一次一个）更适合 ICE。

2. Permission（权限）

为了防止 TURN 被利用成「匿名转发器」绕过企业防火墙，服务器默认拒绝一切入站中继数据。客户端必须显式为每个对端 IP 建立 permission（权限，默认寿命 5 分钟）。来自未授权地址的包被静默丢弃（RFC 5766 §2.3，模仿 NAT 的地址受限过滤）。

3. Channel（通道）

数据传输有两种封装：每次发 Send/Data indication（带完整的对端地址，开销大）或先 ChannelBind 绑定一个 16 位通道号，之后用 ChannelData 消息传（头小得多）。高频大流量走通道，省 20 字节左右/包。

成本：为什么只能当兜底

关键洞见

中继 = 服务器替两端承担全部带宽。RFC 5766 引言说得很直白：「the use of a TURN server … comes at a high cost to the provider … since the server typically needs a high-bandwidth connection」。你的 10GB 文件如果走 TURN，服务器要接收 10GB 再转出 10GB——20GB 的出口带宽，全是你的账单。这就是「relay 优先级为 0」的经济学理由。

另外两个工程事实（RFC 5766 §2.1）：

  • 客户端→服务器可走 UDP / TCP / TLS-over-TCP；服务器→对端永远是 UDP。某些防火墙完全封 UDP 时，TURN over TCP（甚至 443 端口）是唯一活路——这是 getstream 调试清单里「客户站点封 UDP 需要 443 中继」的出处。
  • TURN 分配成功时会顺便告诉你「我看到的你的公网地址」——一个 TURN 服务器同时覆盖了 STUN 的活，生产部署可以只配 TURN。

部署时要防的坑

getstream 文章给出了一份 coturn 配置的心得（原文）：

  • 防开放中继：必须认证（use-auth-secret 临时凭据），否则任何人都能借你的带宽转发流量（匿名中继攻击，RFC 5766 §17.3.2）。
  • 防内网穿透：denied-peer-ip 屏蔽私网段（10/8、172.16/12、192.168/16），防止有人借 TURN 打进你的内网（RFC 5766 §17.2.2）。
  • 配额：user-quota / total-quota 限制并发分配，防 DoS（RFC 5766 §17.3.1）。

对号入座：你的 LocalTransfer

当前 iceServers: []，完全不需要 TURN——局域网内 host 候选直达。未来跨网时，你会先加 STUN（覆盖大多数家庭 NAT），只有 STUN 不够的流量才掉到 TURN。一个实用的容量指标：getstream 建议在生产埋点里统计 relay 占比（选中的候选对是 relay 的比例）——那是你 TURN 带宽预算的预测器。

测验

Q1. TURN 的 Allocate 分配给你的是什么？

  1. 中继传输地址
  2. 公网映射地址
  3. 内网主机地址

Q2. 为什么 TURN 只能是最后手段？

  1. 所有数据都流经服务器
  2. 服务器只中转信令消息
  3. 服务器会加密全部数据

Q3. TURN 的 permission（权限）起什么作用？

  1. 只允许授权的对端发包
  2. 允许所有公网地址发包
  3. 禁止所有对端地址发包

Q4. 分配（allocation）建立后需要定期做什么？

  1. 发送刷新请求维持寿命
  2. 重新协商会话描述内容
  3. 重新执行候选收集流程
