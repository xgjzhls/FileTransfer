## 目标
在线时「打开即见设备」：两端输入同一个 4 位码即自动建房/加入并互见，去掉「创建房间/输入加入」两步角色之分；设备列表与连接体验合一。

## 验收标准（done when）
- [x] 首页输 4 位合法码回车即建房/加入（`/ws?room=X` 对未知码自动建房，服务端零改动），无需先「创建」；同码设备列表即时出现
- [x] 客户端输入约束：仅接受 32 字母表字符（自动剔除/提示 0、O、1、I 等易混淆字符），长度不足 4 无法提交；服务端 `ROOM_CODE_RE` 校验兜底（非法码不再触发 10 次无意义自动重连）
- [x] 「随机生成」按钮：调用 `POST /api/room` 生成合法码并填入输入框，便于口头/截图分享给另一端
- [x] 房间与设备卡片合并为一个「设备」视图：PIN 输入区 + 设备列表（名称/类型/在线状态）+ 点选连接；传输区行为与现状完全一致
- [x] 断线重连（T09）语义不变：WS 断开自动重连原房间，设备列表刷新
- [x] 测试：单测（输入过滤/提交逻辑）+ e2e 新增「双页输入同码 → 互见 → 点选连接」用例，全量跑绿

## 备注
- 服务端 `GET /ws?room=X` 已支持未知码自动建房（Durable Object 按名创建），无需改 `server/`
- `POST /api/room` 保留仅为「随机生成」，可考虑加 `?room=` 参数确认指定码建房（可选，非必需）
- 设备列表交互沿用 T04 的 `peers` + `connectTo`；本次不触碰传输区
