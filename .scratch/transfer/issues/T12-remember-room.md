## 目标
「再次使用零操作」：重开应用自动回到上次的 PIN 房间并恢复设备列表；设备身份跨重载稳定，不留幽灵 presence；失败时优雅降级到扫码入口。

## 验收标准（done when）
- [x] 房间码持久化 `lt.lastRoom`（与 `lt.deviceName` 同模式）；重开应用在线时自动 join 上次房间，设备列表自动恢复，无需手动输入
- [x] 设备身份持久化 `lt.deviceId`（现状每次重载 `crypto.randomUUID()` 换新 → 旧 presence 残留）：重载后以同一身份重连，服务端 presence 无幽灵（结合 T10）
- [x] 自动回房失败（信令离线 / 连续重连放弃）→ 界面降级为「扫码配对」入口，不报错刷屏、不阻塞其他功能
- [x] 手动输入新码加入其他房间时，`lt.lastRoom` 更新为新房间；「退出房间」清除 `lt.lastRoom` 并离开信令
- [x] 设置页新增「退出房间」入口（沿用现有设置页布局）
- [x] 测试：重载自动回房（e2e 双页 + 页面 reload）、身份稳定（同一 deviceId 重连不产生 peer_joined 幽灵广播）

## 备注
- 隐私边界（ADR-0006 后果）：公共网络创建的房间重开时自动重入；房间空则无设备可见，「退出房间」可清除——不改变「房间码即凭证」信任模型
- 待真机验证项（开放问题 #3）：iOS Safari 独立 PWA 模式下后台恢复/重载后的自动回房表现
