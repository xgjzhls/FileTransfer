## What to build

用户诉求本体:收完文件后,**先选目标文件夹,再把选中的多个文件分块流式拷贝进去,不占超大内存**。app 内单文件/分组/多选三种导出入口的主路径都换成「导出到文件夹…」:选文件夹 → 保持相对路径逐段建目录 → 磁盘背书 File 的 stream() 按 4 MiB 分块、JS 显式 base64 过桥写入 → 逐文件进度 → 完成。峰值内存 = 块大小;取消 = 停当前文件、已写保留;重名自动追加序号。

## 方案

- 三种入口(单文件 / 目录组 / 多选勾选)在 app 内统一走「导出到文件夹…」为主路径,复用现有流式链路(磁盘背书 File + stream())
- 相对路径逐段建目录,目录树原生还原,无需 zip
- 分块过桥契约:4 MiB 块、JS 显式 base64(T02 的 writeChunk)
- 进度按文件展示;取消/失败语义明确;重名复用现有消歧逻辑
- 编码优化(FileReader/worker 提升端到端吞吐)**不做,标 [v2]**
