## 目标
设备列表分「在线房间」「局域网发现」两区块；设置页「局域网可见性」开关（默认开）；ADR-0006 可见性门控修订的 UI 落地。

## 验收标准（done when）
1. 两区块并存：在线房间设备（现有，PIN 门控语义不变）+ 局域网发现设备（来源标注「局域网」）；信令不可达（离线）时自动聚焦局域网区块
2. 可见性开关默认开；关闭 = 本机不出现在他人发现列表、也不主动发现；设置持久化（`lt.lanVisible` 模式同 `lt.lastRoom`），重启保持
3. 空态/发现中/失败文案（权限拒绝、无局域网设备、AP 隔离提示降级 QR）
4. 桌面端：局域网区块显示「本地服务器连接的设备」（T08 接入），无发现能力时不出现空误导文案
5. 文档一致：ADR-0006 修订、CONTEXT.md 决策记录同步（无漂移）

## 备注
- 在线/离线边界（ADR-0009 决策 6）：信令可达时在线房间为主，局域网区块仍可显示（app 端）；离线时局域网区块为主
- 视觉上两区块需可区分（标题/来源 tag），避免与现有房间设备混淆

## 实现记录（2026-08-16 落地）

- **可见性开关（验收 2）**：`src/lan/visibility.ts`（`lt.lanVisible`，模式同 `lt.lastRoom`——注入式 StorageLike、'0'=关其余=开默认开、6 单测）＋设置页「局域网」区块 checkbox；**关 = 会话不启动（不广告不浏览，隐身语义）**——Home 的 LAN 会话 effect 以 `lanVisible` 为依赖：关 → 不 start / 重建时 stop，开 → 全量启动（幂等）；断线自动重连（reconnectLan）同步门控（关 → 不重连并提示）。设置页切换后回首页重挂载重新读取，重启保持
- **双区块 UI（验收 1/3）**：设备卡片内分「在线房间」（PIN 门控语义不变，含原 PIN 输入/诊断/设备列表）与「局域网发现」（来源 tag「局域网」+ 每设备行 tag；标题/状态徽标可区分）两 `.device-block`；`signalingDown = !SIGNALING_WSS || wsState==='offline'` 时局域网区块**置前 + accent 描边强调（.lan-primary）**——离线自动聚焦；在线时在线房间为主、局域网区块仍显示（app 端，ADR-0009 决策 6 措辞同步修正，无漂移）
- **空态/发现中/失败文案（验收 3）**：`lanPermissionDenied` 专属引导区块（系统设置 → 本地网络）；普通 `lanError`；「正在发现 / 未发现设备：…AP 隔离时请用离线扫码配对」；「可见性已关闭」说明态
- **桌面端（验收 4）**：非 app 端渲染「本地服务器连接的设备」区块（T08 接入后显示电脑设备），仅说明性文案——无发现能力时**不出现空误导文案**
- **文档同步（验收 5）**：ADR-0009 决策 6 / CONTEXT.md / SPEC §6.1 措辞统一为「在线时在线房间为主、局域网区块仍显示；离线时局域网区块为主」；ADR-0006 修订注已在档
- 测试：visibility 6 个新单测；`npm test` 全绿（487）；tsc -b / oxlint / web+app 双构建绿

## 代码评审修正（/code-review 双轴：Standards + Spec）

- **离线聚焦补全**（Spec）：无 lastRoom 的完全离线首开（ADR-0007 主场景）从不触发 joinRoom，wsState 停在 idle → 原判定永不聚焦局域网区块；现 `signalingDown` 增补 `(wsState==='idle' && room==='')`，并区分徽标文案（信令不可达 / 未加入房间）
- **发现中/启动态区分**（Spec 验收 3）：lanPort===null → 「正在启动局域网发现…」独立文案，与「正在发现/未发现设备」空态区分
- **桌面文案条件化**（Spec）：signalingDown 时桌面区块不再指向「在线房间」，只指引离线扫码配对
