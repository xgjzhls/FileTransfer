# ADR-0002: 纯二维码信令，无中间服务器

- 状态：已接受
- 日期：2024-08-13

## 背景
- 必须离线：无外网信令可用
- 电脑不必在场：手机↔iPad 互传时无任何第三方设备
- 浏览器不能监听端口 → 任何设备都无法当信令中继（信令枢纽方案被排除）

## 决策
信令 = 设备间二维码交换压缩 SDP：
1. A 端生成 offer → gzip 压缩 → 编码二维码
2. B 端摄像头扫码 → 生成 answer → 同样编码二维码
3. A 端扫码 → RTCPeerConnection 建立 → 之后数据直连（信令使命完成）

## 理由
- 二维码是「离线 + 无中间设备」条件下唯一可行的 SDP 交换通道（手动输入不可行——SDP 太大）
- 压缩后、仅含 host + mDNS candidates 的 SDP 可装入单个二维码（QR v40-L ≈ 3KB 二进制）
- 电脑参与的场景同样适用（电脑浏览器显示/扫码），全端架构完全对称，无额外组件

## 后果
- 需要摄像头权限 → 页面必须是安全上下文（HTTPS）→ 见 ADR-0003
- 无设备发现 / 在线列表：二维码即发现机制
- 无 STUN/TURN：仅 host / mDNS candidates；跨子网、AP 隔离会失败（需文档化 fallback）
- 电脑无摄像头时需要「手动粘贴 answer 文本」fallback
- 建连是两次扫码（offer → answer），交互上需向用户讲清楚「谁先扫」
