# ADR-0004: 信令双通道 —— 在线发现 + 离线二维码兜底

- 状态：已接受
- 日期：2024-08-13

## 背景
- 用户需求：打开网页即看到所有开启本页的设备（自动发现）
- 纯离线 + 无中间设备下浏览器无法自动发现（无局域网广播/监听 API；浏览器不能监听端口）
- ADR-0002 的二维码信令保留为纯离线兜底

## 决策
信令 = 单一协议、双载体：
- **在线**：设备通过互联网信令服务加入房间（短房间码），服务广播在线列表（presence）；点选设备 → offer/answer 经 WebSocket 交换 → P2P 直连
- **离线**：降级为二维码交换压缩 SDP（ADR-0002 流程不变）
- 信令服务：自研轻量 WebSocket（统一消息协议：room / presence / offer / answer / candidate），部署首选 Cloudflare Workers + Durable Objects（免费档、零运维），备选自托管 Node

## 理由
- 自动发现在「无中间设备」约束下只有互联网信令一条路
- 单协议双载体：传输层不感知信令载体，二维码路径代码完全复用
- 数据面始终 P2P：信令服务只传元信息，永不接触文件数据；mDNS / host candidates 保证局域网直连

## 后果
- 正面：打开网页即见设备；配对从「谁先扫」变成点一下；纯离线能力保留
- 负面：
  - 自动发现要求设备能访问互联网（数据面不受影响）
  - 需要部署一个小信令服务（CF Workers 免费档足够）
  - 房间码即在场凭证：知道房间码即可见设备（用户接受物理在场/房间在场模型，不设 PIN）
