# ADR-0006: 发现与配对 —— 对称 PIN 房间 + 离线扫码兜底（轻量打磨）

- 状态：已接受（2026-08-15 用户确认）
- 日期：2026-08-15
- 来源：grill-with-docs 访谈（2026-08-15，本地无新建会话）

## 背景

- **痛点**：离线扫码配对需「发送端生成 offer 码 → 接收端扫码 → 接收端显示 answer 码 → 发送端再扫码」来回两趟 + 先选角色，繁琐
- **诉求**：打开页面直接看到局域网设备列表，而不是来回配对
- **技术事实**（2026-08-15 背景研究核实，来源见文末）：
  - 浏览器无 mDNS/DNS-SD 浏览 API；无 UDP 组播/广播；无法监听端口（Direct Sockets 仅限 Chrome IWA；WebTransport 仅客户端）→ **纯浏览器 + 无互联网时无法枚举局域网设备**
  - WebRTC 主机候选在 Chrome 默认 mDNS 混淆、iOS Safari 17/18 完全隐藏 → 拿不到本机局域网 IP，无法做「同子网」分组；本地网络权限（iOS 18 / Chrome LNA）当前也不解锁主机候选
  - Snapdrop 式在线信令按**公网 IP** 分组（同 NAT）是唯一零配对发现模式，但需要联网，且「同公网 IP」≠「同局域网」（代理分流、多子网会误分组）
- **用户决策**（同一访谈）：
  - 主要使用场景经常是纯内网/断网，但**不接受**引入局域网常驻中继（维持「电脑不必在场」「零安装」约束）
  - 设备可见性要求 **PIN 门控**（对应现有「房间码即凭证」模型）
  - 扫码配对**保留为离线兜底**，仅做轻量打磨
  - 交互：设备列表 + 点选连接，传输区保持现状

## 决策

1. **在线发现 = 对称 PIN 房间**：两端输入相同 4 位房间码（32 字母表，排除易混淆字符）即自动建房/加入并互见，去掉「创建/加入」两步角色之分。服务端协议零改动（`/ws?room=X` 对未知码自动建房，Durable Object 按名创建）；`POST /api/room` 保留，仅作为「随机生成一个码」按钮的后端。
2. **客户端房间码输入约束**：仅接受 32 字母表内字符（自动剔除 / 提示 0、O、1、I 等易混淆字符），长度 4；服务端 `ROOM_CODE_RE` 校验兜底（避免非法码触发 10 次无意义自动重连）。
3. **记住上次房间（自动回房）**：房间码持久化到 localStorage（`lt.lastRoom`，与 `lt.deviceName` 同模式）。重开应用在线时自动 join 上次房间、恢复设备列表；自动回房失败 / 信令离线时降级到扫码入口。设置页提供「退出房间」（清除 `lt.lastRoom`）。
4. **离线兜底 = 现有 QR 流程 + 轻量打磨**：扫码自动判定码型（offer/answer）并切换本端角色，无需先选角色；扫码失败自动重试与明确提示；错误文案按场景区分（权限 / 无摄像头 / 占用 / 非安全上下文）；配对成功明确反馈。**不做**中等/大改项（信任设备记忆、配对向导重设计等）。
5. **不引入局域网信令中继**：维持「电脑不必在场」「零安装」；明确接受「纯离线（无互联网）时无设备列表」——该场景下设备列表在纯浏览器中技术上不可行（见背景）。

## 理由

- 对称 PIN 契合「PIN 门控设备列表」心智：输入即互见、无角色概念、复用现有 join 逻辑，服务端零改动
- 不做公网 IP 自动分组（Snapdrop 式）：与「PIN 门控可见」决策矛盾；且用户环境存在代理/Clash（诊断页 fake-ip 现象），公网 IP 分组在代理分流下不可靠
- 记住房间把「再次使用」摩擦降到接近零，在线时兑现「打开即见设备列表」的原始诉求；离线时自动降级，不产生错误体验
- 轻量打磨守住范围：离线路径不是主场景，不值得大改

## 后果

- 正面：
  - 在线时两步直达传输（输码 → 点设备）；二次使用零操作（自动回房）
  - 离线兜底更顺（免选角色、失败可重试、提示清晰）
  - 无约束破坏、无服务端改动、数据面与传输协议不动
- 负面 / 边界：
  - 纯离线仍无设备列表（浏览器技术限制，明确接受）
  - 对称 PIN 碰撞：32^4 ≈ 100 万组合，家庭场景可忽略；碰撞时行为与「两人输同一码」一致（加入同一房间）
  - 记住房间的隐私边界：在公共网络创建的房间，重开时自动重入（无害：房间空则无设备可见；「退出房间」可清除）；不改变「房间码即凭证」的信任模型
  - 房间存活与空房清理策略不随本 ADR 改变（沿用 T10 evict 机制）
  - 待真机验证：对称 PIN 自动回房在 iOS Safari 独立 PWA 模式下的表现（后台恢复 / 重载）
