一次传输的完整链路（点击发送 → 文件落地）

① 信令（L1）  WS 房间 / QR 码 ← 交换 SDP offer/answer（必须双向 → 离线两跳）
                  ↓
② SDP（L2）   m=application 9 UDP/DTLS/SCTP webrtc-datachannel
              a=ice-ufrag/pwd（打洞凭据）· a=fingerprint/setup（DTLS）
              a=sctp-port · a=max-message-size:262144（=你的 256KiB−64 帧来源）
              a=candidate … typ host（局域网只有 host）
                  ↓
③ NAT（L3）   内网可出、入站默认丢 → P2P 需要「可被找到」
              四分类：全锥/限制锥/端口限制锥/对称（映射 × 过滤）
              对称 NAT = 每目的地一个映射 → STUN 失效
              映射会过期（有的 20s）→ keepalive / consent freshness
                  ↓
④ ICE（L4）   收集(host/srflx/relay/prflx) → 交换 → 配对 → 连通性检查 → 提名
              检查 = 从 base 发 STUN Binding Request（探路 + 打洞同时完成）
              控制方(发起方)提名 USE-CANDIDATE；被控方确认
              优先级：host > srflx > prflx > relay(0)
                  ↓
⑤ 打洞（L5）  会合服务器互换公/私端点 → 双方同时向对方公网发包
              各自的 NAT 把「入站」当成「出站回包」→ 洞开 → 直连
              对称 NAT 失败；prflx 可能救场；洞会关，需保活
                  ↓
⑥ TURN（L6）  打洞失败的最后手段：Allocate 中继地址（10min 寿命需 Refresh）
              Permission 按对端 IP 授权（防匿名中继）· Channel 降低开销
              代价 = 服务器替两端承担全部带宽 → relay 优先级 0
              客户端↔服务器可走 UDP/TCP/TLS；服务器↔对端恒 UDP
                  ↓
⑦ 数据面（L7）DTLS 加密 → SCTP（有序/可靠、分片、拥塞控制）→ DCEP 建通道
              Channel Type 0x00 = 可靠有序（你的 ordered:true）
              PPID：50=DCEP / 53=二进制帧 / 51=字符串
              背压：bufferedAmount > 8MiB 暂停，bufferedamountlow 唤醒
              → 你的 256KiB 帧 → 64MiB bitfield 续传 → OPFS 落盘

你的项目当前所处位置

  • 信令：WS + QR 双载体，单协议 SignalPayload { kind: 'offer'|'answer', sdp }（L1）
  • 非 trickle 单次装载：等 gathering complete 后 gzip+b64 一次发出（L2）
  • iceServers: [] → 仅 host 候选；局域网直达，无需 NAT 穿越（L3–L4）
